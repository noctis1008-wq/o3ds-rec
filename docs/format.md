# .3dr 録画フォーマット v1

数値はすべてリトルエンディアン。チャンクは時刻（tick）順に並ぶ。

## ファイルヘッダ（512バイト）

| オフセット | 型 | 内容 |
|---|---|---|
| 0 | char[4] | `3DRC` |
| 4 | u16 | バージョン = 1 |
| 6 | u16 | ヘッダサイズ = 512（以降の書き込みを SD のセクタ境界に揃えるため） |
| 8 | u32 | tick 周波数 = 268111856（ARM11 システムティック） |
| 12 | u32 | フラグ（予約、0） |
| 16 | u64 | 録画開始 tick（動画の 0 秒） |
| 24 | — | 予約（0、512 バイト目まで） |

## チャンクヘッダ（16バイト）

| オフセット | 型 | 内容 |
|---|---|---|
| 0 | char[4] | 種類: `VFRM` 映像 / `AUDI` 音声 / `EOS ` 終端 |
| 4 | u32 | ペイロード長 |
| 8 | u64 | tick（そのフレームが画面に出た時刻） |

## VFRM（映像フレーム）

| オフセット | 型 | 内容 |
|---|---|---|
| 0 | u8 | 画面: 0=上(左目) / 1=下 / 2=上(右目) |
| 1 | u8 | ピクセル形式（GSP と同じ）: 0=RGBA8 1=BGR8 2=RGB565 3=RGB5A1 4=RGBA4 |
| 2 | u16 | ライン数（上 400 / 下 320） |
| 4 | u16 | 1ラインのバイト数（240 × bpp） |
| 6 | u16 | フラグ: bit0 = キーフレーム（全ライン入り） |
| 8 | u32 | 画面ごとの通し番号 |
| 12 | u8[ceil(ライン数/8)] | 変化ラインのビットマップ（ライン i は byte i/8 の bit i%8） |
| … | — | 変化したラインの生データを、ライン番号の昇順に詰めたもの |

- 3DS のフレームバッファは 90 度回転して格納されている。**1ライン = 画面の縦1列（240px）**、ライン番号 = 画面の x 座標、ライン内の先頭ピクセルが画面の一番下。
- 前フレームと完全に同じ画面は書かない。変換ツールは直前の絵を保持して時間を埋める。
- 形式が変わったとき・キーフレーム間隔ごとにキーフレームを入れる（途中から壊れても復帰できる）。

## AUDI（音声）

| オフセット | 型 | 内容 |
|---|---|---|
| 0 | u32 | サンプリング周波数（3DS DSP は 32728 Hz） |
| 4 | u16 | チャンネル数 |
| 6 | u16 | 形式: 1 = PCM16LE |
| 8 | — | サンプルデータ |

## 分割

FAT32 の 4GB 制限があるため、3.5GB 前後で `REC_xxxx.3dr` → `REC_xxxx.part2.3dr` … に分割する。
各分割ファイルは同じファイルヘッダで始まり、**ヘッダ以降のデータは全ファイルを通して1本のチャンク列**になる（チャンクがファイルの境目をまたいでよい）。

## 末尾

書き込みを速くするため、3DS 側はファイルを先に大きめに確保する。正常終了時は実サイズに切り詰めるが、電源断などで残った場合、チャンク種類が `\0\0\0\0` の位置をデータの終わりとみなす。
